Case-Based Reasoning for Smart Navigation & Delivery System

What is Case-Based Reasoning (CBR)?

CBR is a problem-solving approach that solves new problems by retrieving and adapting solutions from a past case library. In a smart delivery system, it enables the platform to reuse proven routes instead of planning from scratch.

The CBR Cycle

1. Retrieve

Match a new problem (new delivery order) against the case memory to find the most similar past route.

2. Reuse

Adapt the retrieved route to current conditions (traffic, road closures, time of day).

3. Revise

Refine the adapted route based on real-time feedback and update the case memory.

4. Retain

Store the new case (or updated version) in the case memory for future reuse.

Case Memory Design

Tabular Representation

Case ID Origin Destination Traffic Conditions Time of Day Estimated Time Status
R-001 Downtown Hub Westside Warehouse Light traffic 08:00 AM 45 min Active
R-002 Westside Hub North District Center Heavy traffic 14:30 PM 60 min Active
R-003 North District Hub Eastside Warehouse Moderate traffic 19:00 PM 50 min Active

Discrimination Tree (Indexing)

  • Destination Coordinates (x, y, z) – used for spatial similarity
  • Time of Day (morning, afternoon, evening, night) – temporal context
  • Traffic Conditions (light, moderate, heavy) – road state
  • Route Length – total distance
  • Historical Success Rate – past performance

Indexing Strategy: Each case is indexed by a composite key combining these attributes. The most similar case is found by computing a similarity score (e.g., cosine similarity on normalized vectors).

Worked Example

Scenario: New Delivery Order

When a new order arrives from Westside Hub to North District Center at 14:30 PM, the system performs the following:

  1. Retrieve: The system searches the case memory and finds R-002 (Westside Hub → North District Center at 14:30 PM, moderate traffic, 60 min).
  2. Reuse: The base route from R-002 is loaded as a template.
  3. Revise: Current conditions show heavy traffic and evening time. The system adjusts the route by adding a detour around the congestion zone and extending the estimated time to 75 min.
  4. Retain: The updated case R-002-modified is stored in the memory with a new status.

Result: The delivery driver follows the adapted route, arriving 15 minutes earlier than the original estimate despite the traffic.

Tabular vs. Tree-Based Retrieval

Aspect Tabular (Indexed List) Tree-Based (Discrimination Tree)
Search Speed O(n) – linear scan of all cases O(log n) – hierarchical traversal
Flexibility Good for simple key lookups Excellent for multi-dimensional similarity
Memory Overhead Low – just store case records Higher – need tree structure, indexes
Handling New Cases Append to list Insert into appropriate branch
Staleness Management Manual refresh Automatic pruning of outdated branches

Recommendation: Use a hybrid approach – a fast tabular index for initial filtering, then a discrimination tree for fine-grained matching.

Keeping the Case Base Manageable

Preventing Growth

  • Periodic Pruning: Remove cases older than X months or with low reuse rate.
  • Similarity Thresholding: Discard cases whose similarity score falls below a minimum.
  • Versioning: Keep only the best version of each route; discard obsolete variants.
  • Caching: Store frequently accessed cases in memory for O(1) retrieval.
  • Automatic Archiving: Move rarely used cases to cold storage (e.g., S3) instead of deleting.

Handling Staleness

As traffic patterns change, old routes may become suboptimal. The system should:

  1. Recompute similarity scores periodically.
  2. Flag routes with degraded performance.
  3. Trigger a Revise cycle when a route is marked stale.
  4. Periodically re-index the case memory to reflect current conditions.

Key Takeaways

  • CBR enables smart delivery systems to reuse proven routes instead of planning from scratch.
  • The CBR cycle (Retrieve → Reuse → Revise → Retain) provides a structured decision process.
  • Index attributes like destination coordinates, time of day, and traffic conditions enable effective discrimination.
  • Tabular indexing offers speed; discrimination trees offer precision – use both together.
  • Regular pruning, versioning, and caching keep the case base from growing uncontrollably.
